# Module map — Ka0s Skill Master

Every non-vendored file the TOC loads, in load order, with its one responsibility. The TOC's `#`
section headers fix the folder order `libs → locales → core → defaults → modules → settings`
(layout-§1); inside `core/` the order is what each file resolves at load, and each load-bearing
position says so beside its TOC line (toc-file-§5).

`Bindings.xml` sits at the root beside the TOC and is never a TOC line (launcher-§6). It carries seven
`CLICK` bindings, Show window (the Professions window) first, then the other five family windows, then the
Journal; `modules/MainWindow.lua` creates every button (`SkillMasterToggleWindow`, `SkillMasterToggleSkills`,
`...Stats`, `...Currencies`, `...Reputations`, `...Statistics`, `SkillMasterToggleJournal`), their labels and
`NS.BINDINGS`.
The waypoint arrow's art is the library's (`libs/LibKa0s/media/waypoint/`, round 8, R8-5); the
round-6 `media/waypoint/` copy is gone.
`tools/seeds/` is dev-only and never loaded or packaged (`.pkgmeta` ignores `tools`): `seeds.py` re-validates
the trainer, fishing-zone and skill-catalog seeds against WoW Forever's DB2, and the trainers and gathering
nodes against ForeverDB as secondary evidence ([validate-seeds.md](validate-seeds.md)),
`forever_rulings.json` holds its rulings (written only by `seeds.py rule`), `test_seeds.py` its offline tests.
`tools/trainer_probe.lua` and `tools/trainer_probe/` are dev-only too (GitHub issue #3): the offline trainer
probe, run from the shell (`lua tools/trainer_probe.lua <QuestieDB> ...`), checks every trainer record against
QuestieDB's Forever NPC table, cross-checks it with the CMaNGOS 1.12 dump (ItemTree's method), pfQuest and a
Method.gg names list, and writes `docs/trainer-probe/<run>/` and `defaults/TrainerProvenance_Forever.lua`
(the modules: `io`, `questiedb`, `cmangos`, `pfquest`, `checks`, `era`, `report`; tests in
`tests/test_trainer_probe.lua`).
`libs/` and `tests/_kit/` are vendored from LibKa0s v1.117.0 (the root `CLAUDE.md` provenance line) and never
edited.
