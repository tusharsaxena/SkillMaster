## Title-bar and header-strip controls (rulings 3 and 4)

Every one of these controls is an `NS.Chrome` mark (`IconButton` / `HeaderMark`) or the library's
close (`Core.MakeCloseButton` with this addon as owner, through `NS.MakeCloseButton`). The fix is
in `NS.Chrome`, so it reaches every window at once. **`W.HeaderButtons` was not adopted.** The
library surfaces used are `LibKa0s-Tooltip-1.0`'s `AttachTitleTip` and the skin facade's
`Mark`/`Color`.

- **Tooltips.** Each mark's `tip` is now shown through `AttachTitleTip(b, fn, "SkillMaster")`. The
  text is read on each hover, owned at `ANCHOR_NONE`, placed above the mark by `PlaceAttached`
  (below only when there is no room) and drawn in the owner's `gtip.title`. Before this, the tip
  was the game tooltip at `ANCHOR_TOP` in its default color. Without the library, the old path
  still runs. The close already had "Close" from the library.
- **Colors.** `NS.Chrome.REST = "icon.tint"` is the rest color and `NS.Chrome.HOT = "text.link"`
  is the hover color. The glyph fallback uses the same two. The close keeps the library's
  `close.rest`, which follows `icon.tint`, and `close.hot`. These marks have no glow of their own.
- **Superseded.** Round 2's and round 8's (R8-3) `text.heading` rest on the block-header and band
  marks is gone, because ruling 4 says `icon.tint` for every control. R8-3's invariant still holds:
  the band marks match the main window header's marks. The filled filter badge is still the state
  signal. Its square is the mark's rest color (`icon.tint`), and under the pointer it turns
  `text.link`.
- **Not a title-bar control.** The row's action mark (`ph:sign-in`) keeps `icon.hot` through
  `button.hotToken`.

| Window | Controls | Tooltip | Rest / hover |
|---|---|---|---|
| Main window title bar | close, lock, journal, settings, collapse/expand all | Close; Lock or unlock the window; Open the journal; Open the settings panel; Collapse all blocks / Expand all blocks | close `close.rest`/`close.hot`; marks `icon.tint`/`text.link` |
| Journal title bar | close, lock | Close; Lock or unlock the window | as above |

Two new enUS keys: `Collapse this block` and `Expand this block`.

## Header bands (ruling 5)

`sm.headerBg` keeps `follow = "list.header.bg"` and its default of black .35. In Ka0s Default, an
owner token answers its `default`, and the re-cut library's Ka0s Default `list.header.bg` is now
black .35 as well. Every other skin follows the token. So the band now resolves to
`list.header.bg` in all nine skins with no code change, and `tests/test_sr1.lua` pins this per
skin, including the band the block header paints. That case was green when it was written,
because the library change had already made it true. A mutation check (default set to .30) turned
it red for `ka0s`, and the value was then restored.

## Tests

`tests/test_sr1.lua` has 10 cases. One per window checks that every control shows a non-empty
tooltip above it, owned at `ANCHOR_NONE`, in `gtip.title`, and hidden on leave. One case checks
rest and hover colors in all nine skins. One checks the filter badge, and one checks the header
band in each skin. The tooltip and color cases were red before the change: the tips were
`ANCHOR_TOP`, the chevrons had no tip, the hover was `icon.hot` and the badge was `text.heading`.
Re-pinned to the new ruling, with nothing weakened: `test_round2_icons` (detach rest and hot),
`test_round5_followups` and `test_round7` (the badge and rest token), and `test_round8` (band
rest, hover and badge hot).
