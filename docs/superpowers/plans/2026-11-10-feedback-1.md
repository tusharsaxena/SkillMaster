# Skill Master feedback round 1: implementation plan and ledger

**Goal:** act on the owner's first in-game feedback (2026-11-10). Make the Bars page and its Marks
settings take effect. Replace the empty template dropdowns with presets plus a custom text box. Give
skill and stat rows one shared "Rows show" setting. Split the client-quirks doc per client, upstream
in the standard and in dev-copilot, then apply that split here.

**Resumable:** each task has a ledger row below. A task is done when its commit exists on the
branch named in the row. To resume, read the ledger, check `git log` on each branch, and restart the
first task that is not done.

## Owner decisions (2026-11-10)

| Question | Answer |
|---|---|

## My calls

- **Promotion bar for the Forever catalog:** an engine behavior the Retail catalog already promoted may
  enter the Forever catalog on one repo's measurement on Forever, because the two-repo bar was met when
  it was first promoted. A behavior new to Forever needs two repos, as usual. A one-repo Forever finding
  stays in the addon's own section.
- **Skill Master's own Forever findings** stay in its own section of `docs/forever-quirks.md`: the
  `C_SkillInfo` struct, the enchant slot and the duplicate profession lines are each one repo.
- **Standard version:** v2.107.0 (renumbered at merge if master moved). **dev-copilot:** 2.10.0.

## Tasks

- **FB-0 (setup):** merge the v1 run, clean it up, file #1, create the branches and worktrees.
- **FB-1 (Bars and Marks take effect):** trace each Bars-page row (heights, fill direction, texture,
  opacity, color, background, border, text, font, and the four Marks) from its setter to every surface
  that draws a bar: main-window rows, detached blocks, the row tooltip, the broker tooltip mini bars,
  the journal and the settings preview. Fix whatever drops the change. Pin each row with a headless test

  setting it governs is meant to be ignored. That is not a bug, but the page must make it visible.

  get a presets dropdown plus "Custom…", which reveals an edit box. The stored value stays the template
  string. Remove the empty-dropdown diagnostics warning. Add tests.
- **FB-3 (global Rows show):** one setting (Bar and value / Bar only / Value only) read by skill rows and
  stat rows on every surface that draws rows. Migrate an existing `stats.display` once
  (savedvariables). Add tests.
- **FB-4 (standard, per-client quirks):** add the Forever catalog section `forever-quirks` and state that
  `client-quirks` is the Retail catalog. Make documentation-§3 Tier 2 per client. Ripple the change
  through the index, AUDIT.md, NEW_ADDON_CONTEXT, CLAUDE.md, EXECUTIVE_SUMMARY, the version stamps and
  the CHANGELOG. Seed the Forever catalog. `scripts/check-standard.sh` must pass.
- **FB-5 (dev-copilot, per-client quirks):** update harvest (read both files, route each finding to its
  client's catalog), revendor-standards (refresh each file's vendored block, create `forever-quirks.md`,
  retire `midnight-quirks.md` in a Forever-only addon by `git mv`), the audit agent (Tier 2 per client),
  wow-new-addon (born per the addon's Clients value), and the review and sync-docs overlays. Bump to
  2.10.0. `scripts/check_overlays.py` and the unit tests must pass.
- **FB-6 (Skill Master's quirks doc):** `git mv docs/midnight-quirks.md docs/forever-quirks.md`, vendor the
  Forever catalog block, keep Skill Master's own section, and update every live reference. Frozen
  bundles keep the old name.
- **FB-7 (integrate and verify):** merge `fb/bars` and `fb/templates` into the integration branch, run the
  full gate, run adversarial verifiers on all three repos, fix what they confirm, then push.
- **FB-8 (merge, after the owner's go):** rebase onto origin, merge the three repos, delete every branch
  and worktree this run made.
