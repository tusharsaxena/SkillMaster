# Dependencies — Ka0s Skill Master

What you need installed to build, run, test or release this addon. Commands are for
**WSL2 / Ubuntu** (the collection's development environment). How to *verify* the addon once
you are set up is `docs/testing.md`; this file only covers *what to install*.

Every entry says what needs it and how that is known. Anything only plausibly required is
marked as such rather than listed as a requirement.

## Runtime (in-game) — what a player needs

- **World of Warcraft: WoW Forever** (client 1.60.1). `SkillMaster.toc` carries one `## Interface: 16001`
  line plus the Forever load-gating pair (`## AllowLoadGameType: camelot`, `## ExcludeLoadGameType: standard`),
  so Retail does not list the addon (toc-file-§3, clients-§9).
- **Nothing else.** Every library is vendored under `libs/` and committed (library-stack), so the
  player installs no separate library addon. `## OptionalDeps:` names the vendored libs for load
  ordering, not as things to download.

## Development — the contributor toolchain

| Tool | Version | Needed for | Evidence |
|---|---|---|---|
| `lua5.1` (+ `luac`) | **5.1 exactly** | the headless suite, `KA0S_KIT_CLIENT=forever lua tests/run.lua` | `tests/_kit/loader.lua` uses `setfenv` |
| `luacheck` | any recent | `luacheck .`, the other half of the green gate | `.luacheckrc` at the repo root |
| `lizard` | any recent | the `complexity` suite of `tests/_kit/run-automated-tests.sh`, which runs it over a sanitized shadow (automated-tests-§3) | `lizard --version` |
| `git` | any recent | vendoring; the kit's eol, prose, skin-values and client-globals suites read `git ls-files` | `tests/_kit/test_eol.lua` |
| POSIX shell | any | the commands in this file and in `docs/testing.md` | — |

**Lua 5.1 is a requirement, not a preference.** The harness sandboxes each source file with
`setfenv`, which was removed in 5.2.

```sh
# Lua 5.1 and luacheck
sudo apt-get update
sudo apt-get install -y lua5.1 luarocks
sudo luarocks install luacheck

# lizard — via pipx, NOT pip (Ubuntu 24.04 marks its Python EXTERNALLY-MANAGED, PEP 668)
sudo apt-get install -y pipx
pipx ensurepath          # then open a new shell
pipx install lizard

# verify — each of these must print a version
lua5.1 -v
luacheck --version
lizard --version
git --version
```

## Release / assets

**One entry: Pillow**, and only for **regenerating** the logos — `media/logos/skillmaster.logo.tga`
(300x300) and `skillmaster.logo.128.tga` (128x128, uncompressed 32-bit) are committed, generated by
hand from `skillmaster.logo.png` with layout-§4's recipe
(`Image.open(src).convert("RGBA").resize((128, 128), Image.LANCZOS).save(out, format="TGA")`).
The waypoint arrow's art is no longer this addon's: since round 8 (R8-5) it ships in the vendored
`libs/LibKa0s/media/waypoint/`, generated in the library repo by its `tools/artwork/waypoint_arrow.py`,
so nothing here regenerates it. **None of this group is required to build, run or test the addon.**

```sh
sudo apt-get install -y python3-pil
python3 -c "import PIL; print(PIL.__version__)"
```

## Am I set up correctly?

```sh
KA0S_KIT_CLIENT=forever lua tests/run.lua             # the suite — must be green (Forever profile only)
~/.claude/dev-copilot/bin/ka0s-bounded luacheck .     # must be 0 warnings / 0 errors
~/.claude/dev-copilot/bin/ka0s-bounded bash tests/_kit/run-automated-tests.sh --suite complexity --no-bundle
                                                      # the sighted complexity report (release-time)
```

See `docs/testing.md` for what those commands mean and when each is run.
